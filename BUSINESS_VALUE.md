# SwiftMigrator6 — бизнес-ценность

SwiftMigrator6 сокращает стоимость перевода iOS/macOS-проекта на Swift 6 за счёт автоматического исправления типовых ошибок строгой конкурентности и точечной помощи LLM в сложных случаях.

- **Проблема.** Включение языкового режима Swift 6 в реальном проекте даёт сотни и тысячи ошибок компиляции. Команды откладывают миграцию, потому что не понимают объём работ и порядок действий.
- **Решение.** Инструмент анализирует проект, строит граф модулей и порядок миграции, классифицирует ошибки и разводит их по трём маршрутам: автоисправление по правилу, LLM с минимальным контекстом, ручная работа.
- **Ценность.** Предсказуемый план и объём миграции до старта работ, автоматическое закрытие однотипных ошибок, проверка каждого изменения компилятором.
- **Целевой показатель.** Не менее 70% ошибок строгой конкурентности устраняются автоматически или полуавтоматически.

## Зачем переводить проекты на Swift 6

Swift 6 — единственный режим языка, в котором гонки данных ловит компилятор, а не пользователи в виде крашей.

1. **Гонки данных становятся ошибками компиляции.** Режим Swift 6 диагностирует потенциальные data races как errors ([swift.org](https://www.swift.org/blog/announcing-swift-6/)). В Swift 5.10 те же проверки были лишь предупреждениями.
2. **Гонки — самый дорогой класс багов.** Они недетерминированы, плохо воспроизводятся на машине разработчика и проявляются как редкие краши и повреждение данных в проде. Исправить их на этапе компиляции дешевле, чем расследовать по краш-отчётам.
3. **Инструменты уже на Swift 6.** С 28 апреля 2026 App Store принимает только сборки Xcode 26 и выше ([Apple](https://developer.apple.com/news/upcoming-requirements/)), а он поставляется с компилятором Swift 6.2. Режим Swift 5 пока поддерживается, но новые API и примеры Apple пишутся под строгую конкурентность.
4. **Экосистема уходит вперёд.** Библиотеки переходят на Swift 6 и публикуют API с `Sendable` и изоляцией акторов. Немигрированный проект копит предупреждения и обходные `@preconcurrency`.
5. **Техдолг растёт с каждым релизом.** Каждый новый модуль на Swift 5 — ещё один модуль, который придётся мигрировать позже.

## Что даёт Swift 6

Главный бонус — гарантия отсутствия гонок данных; остальные возможности становятся удобнее после миграции.

| Возможность | Версия | Бизнес-эффект |
| --- | --- | --- |
| Проверка data races компилятором | 6.0 | Меньше плавающих крашей, выше crash-free rate |
| `Sendable` и изоляция акторов в типах | 6.0 | Контракт потокобезопасности виден в коде, быстрее ревью и онбординг |
| Typed throws | 6.0 | Исчерпывающая обработка ошибок без кастов |
| Synchronization: `Mutex`, `Atomic` | 6.0 | Стандартные примитивы вместо самописных обёрток над локами |
| Swift Testing | 6.0 | Параметризованные тесты, параллельный запуск |
| Изоляция `@MainActor` по умолчанию, `@concurrent` | 6.2 | Меньше аннотаций в UI-коде, явный параллелизм |
| `InlineArray`, `Span` | 6.2 | Безопасная работа с памятью без накладных расходов |

Источники: [Swift 6](https://www.swift.org/blog/announcing-swift-6/), [Swift 6.2](https://www.swift.org/blog/swift-6.2-released/). Часть возможностей доступна и в режиме Swift 5, но гарантия отсутствия гонок — только в режиме Swift 6.

## Почему команды не мигрируют сами

Миграция дорога не сложностью отдельной ошибки, а их количеством и взаимными зависимостями.

- **Масштаб.** В коммерческих проектах включение `-strict-concurrency=complete` даёт сотни–тысячи диагностик. Точные цифры по корпусу из 5–10 открытых проектов даст этап 0 диплома.
- **Однотипность.** Большая часть ошибок — повторяющиеся шаблоны: глобальные `var`, UIKit-классы без `@MainActor`, неизменяемые структуры без `Sendable`. Вручную это часы механической работы инженера.
- **Порядок модулей.** Исправление в базовом модуле меняет ошибки во всех зависящих. Начать не с того модуля — значит переделывать.
- **Непредсказуемый срок.** До начала работ нельзя оценить объём, поэтому миграцию не ставят в план спринта.
- **Риск регрессий.** Быстрые обходы (`nonisolated(unsafe)`, `@unchecked Sendable`) убирают ошибку, но не гонку.
- **Существующие средства точечны.** Фикситы Xcode и поэтапный `-strict-concurrency` работают с одной диагностикой за раз и не дают картины проекта целиком.

## Как помогает SwiftMigrator6

Инструмент закрывает полный цикл от анализа до проверенного компилятором исправления; каждая функция бьёт в одну из причин выше.

| Функция | Какую проблему решает | Статус |
| --- | --- | --- |
| Анализ проекта (SPM, xcodeproj) и dry-run отчёт | Непредсказуемый срок: объём виден до старта | CLI `analyze` / `report` — каркас готов |
| Граф модулей + топологическая сортировка | Порядок модулей: миграция от листьев к корню | Этап 1 |
| Сбор диагностик компилятора (сериализованные, не regex) | Масштаб: все ошибки сразу, с привязкой к модулю | Этап 1 |
| Классификатор: авто / LLM / вручную | Видно, какая доля работы автоматизируется | Порты и модель готовы, правила — этап 2 |
| Детерминированные фиксы на swift-syntax: `@MainActor` для UIKit, `Sendable` для структур, `var` → `let`, `@preconcurrency import` | Однотипность: шаблоны закрываются без участия человека | Этап 2 |
| Правило «не уверен — не трогай» (`FixProposal?` = `nil`) | Риск регрессий: лучше меньше покрытие, чем сломанный код | Заложено в контракт `FixRule` |
| LLM-слой с минимальным контекстом (тип + места использования + соседи по графу) | Сложные случаи, стоимость пропорциональна сложности ошибки | Порт `LLMProvider` готов, реализация — этап 3 |
| Diff-превью и явное подтверждение | Разработчик контролирует каждое AI-изменение | Этап 3–4 |
| Верификация перекомпиляцией + откат через Git | Ни одно изменение не принимается, если ошибок стало больше | Этап 2 |
| macOS-приложение: дашборд, интерактивный граф | Картина прогресса для команды и менеджмента | Скелет UI готов, экраны — этап 4 |

Архитектура ports & adapters: лоадер, классификатор, правила и LLM-провайдер заменяются без правки ядра. Одно ядро работает и из CLI (для CI), и из приложения.

## Почему это лучше, чем AI-агент

Агент решает каждую ошибку заново и вероятностно; SwiftMigrator6 закрывает шаблоны правилами, а LLM зовёт только там, где нужен контекст.

| Критерий | AI-агент (Claude Code, Cursor, Copilot) | SwiftMigrator6 |
| --- | --- | --- |
| Воспроизводимость | Два запуска дают разные патчи | Один вход — один результат для детерминированных правил |
| Корректность шаблонных фиксов | Вероятностная; может «починить» через `@unchecked Sendable` или `nonisolated(unsafe)` | Трансформация AST с юнит-тестами «до/после»; сомнение = отказ |
| Масштаб | Большой проект не помещается в контекст, агент видит код фрагментами | Граф всего проекта строится без LLM; модели — только выборка на ошибку |
| Порядок миграции | Идёт по списку ошибок, без графа модулей | Топологический порядок: сначала базовые модули |
| Стоимость | Токены тратятся на каждую ошибку, включая тривиальные, и на чтение файлов | Шаблоны — 0 токенов; LLM — только остаток с минимальным контекстом |
| Контроль | Много файлов меняется за шаг, ревью тяжёлое | Изменения пакетами по модулю, diff на каждое AI-исправление, откат через Git |
| Приватность кода | Код уходит в облако целиком по мере чтения | Детерминированный слой работает офлайн; наружу — только фрагменты; провайдер заменяем (в т.ч. локальная модель) |
| Измеримость | Нет отчёта «сколько осталось» | Dry-run отчёт: всего / авто / AI / вручную, прогресс по модулям |
| Использование в CI | Интерактивный инструмент, нестабильный вывод | CLI с `--json` и кодами возврата |

Инструмент не отказывается от LLM, а сужает её роль: агент остаётся исполнителем для сложных случаев внутри контролируемого пайплайна. Цифру экономии токенов (токены на ошибку против токенов на весь проект) даст этап 3.

## Для кого и как измеряем эффект

Целевая аудитория — команды со средними и крупными многомодульными iOS/macOS-проектами (30К+ строк), для которых ручная миграция — недели работы.

- **Тимлид / техлид:** оценка объёма и план по модулям до старта работ.
- **Разработчик:** механические правки делает инструмент, человек занимается архитектурными случаями.
- **Менеджмент:** прогресс миграции в цифрах, а не «ещё не знаем».

Метрики эксперимента на корпусе из 5–10 открытых проектов (заполняются на этапе 5):

| Метрика | Цель | Факт |
| --- | --- | --- |
| Доля ошибок, устранённых автоматически или полуавтоматически, % | ≥ 70 | |
| Доля детерминированных фиксов, сломавших компиляцию или тесты, % | 0 | |
| Доля принятых AI-исправлений, % | | |
| Токены на ошибку против токенов на весь проект | | |
| Время миграции модуля: инструмент против вручную / агента, ч | | |
| Стоимость API на проект, $ | | |

Строка «время против агента» — прямое доказательство тезиса из раздела выше; без неё сравнение с агентом остаётся аргументом, а не фактом.
